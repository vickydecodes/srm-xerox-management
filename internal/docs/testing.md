# Backend API Testing Guide

This documentation outlines the DRY testing pattern established for backend integration testing. It utilizes dynamic route base configurations, HTTP supertest wrappers, automatic mock authentication, and Chai-style assertions that validate responses against standard middleware wrapper structures.

---

## 📂 Core Testing Architecture

The backend integration testing framework consists of three key components:

1. **Route Endpoint Definition ([`branch.route.ts`](../../backend/src/modules/branch/branch.route.ts))**: Routers export their base paths and endpoints, ensuring changes in routes automatically propagate to tests.
2. **Test Helper Utility ([`tester.constant.ts`](../../backend/src/core/constants/tester.constant.ts))**: Exposes DRY request methods (`get`, `post`, `put`, `patch`, `del`), automatic database setup/teardown for authenticated tests (`setupAdmin`), and assertions matching the structure of `sendResponse`.
3. **Test Cases ([`branch.test.ts`](../../backend/src/tests/branch.test.ts))**: Test files that use these utilities to run comprehensive, readable integration assertions.

---

## 🛠️ The `tester` Helper Utility

All test assertions and helper utilities are centralized in [`tester.constant.ts`](../../backend/src/core/constants/tester.constant.ts).

### 1. HTTP Request Helpers
These helpers wrap `supertest(app)` and automatically append authorization headers:

| Method | Signature | Description |
| :--- | :--- | :--- |
| `get` | `tester.get(url, token?)` | Hits a `GET` endpoint. |
| `post` | `tester.post(url, body, token?)` | Hits a `POST` endpoint with request payload. |
| `put` | `tester.put(url, body, token?)` | Hits a `PUT` endpoint with request payload. |
| `patch`| `tester.patch(url, body, token?)`| Hits a `PATCH` endpoint with request payload. |
| `del` | `tester.del(url, token?)` | Hits a `DELETE` endpoint. |

### 2. User Authentication & Database Setup
The helper `setupAdmin` creates a mock admin on the fly and returns a cleanup callback for teardown:

```typescript
const setup = await tester.setupAdmin();
const token = setup.token;      // User JWT Token
const cleanup = setup.cleanup;  // Async function to delete the mock user in afterAll
```

### 3. Response Structure Assertions
These match the standard fields generated by [`responsewrapper.constant.ts`](../../backend/src/core/constants/responsewrapper.constant.ts):

```typescript
// Assert 200 OK with custom message and data checks
tester.assertSuccess(res, "Branch retrieved successfully", (data) => {
  expect(data.code).to.equal("TBR");
});

// Assert 201 Created structure
tester.assertCreated(res, "Branch");

// Assert 200 Updated structure
tester.assertUpdated(res, "Branch");

// Assert Paginated/Array Fetched structure
tester.assertFetched(res, "branch");

// Assert 200 Deleted structure
tester.assertDeleted(res, "branch");

// Assert 404 Not Found structure
tester.assertNotFound(res, "branch");

// Assert 400 Bad Request Zod/validation error
tester.assertValidationError(res);
```

## 🚀 Router Export Pattern

To keep URLs DRY, routers export their base path properties. For example, in [`branch.route.ts`](../../backend/src/modules/branch/branch.route.ts):

```typescript
export const basePath = '/branches';
export const baseRoute = `/api/v1${basePath}`;

const router = Router();
// router.post('/', ...)
```

The autoloader matches `basePath` for server mounting, and integration tests import `baseRoute` directly to map their requests.

## ✍️ How to write a new API Test

Creating an integration test for a new module is simple. Follow this boilerplate template:

```typescript
// src/tests/product.test.ts
import { describe, it, beforeAll, afterAll } from 'vitest';
import mongoose from 'mongoose';
import { bootstrap } from '../app.ts';
import Product from '@db/models/product.model.ts';
import { tester } from '@core/constants/tester.constant.ts';
import { baseRoute } from '../modules/product/product.route.ts'; // Import route dynamically!

let token: string;
let cleanupAdmin: () => Promise<void>;
let createdProductId: string;

beforeAll(async () => {
  await bootstrap();
  const setup = await tester.setupAdmin();
  token = setup.token;
  cleanupAdmin = setup.cleanup;
});

afterAll(async () => {
  if (cleanupAdmin) await cleanupAdmin();
  await Product.deleteMany({ code: 'TEST_PROD' });
});

describe('Product API Integration Tests', () => {
  it('should successfully create a product', async () => {
    const res = await tester.post(baseRoute, {
      name: 'Test Product',
      code: 'TEST_PROD',
      price: 15.00
    }, token);

    tester.assertCreated(res, 'Product', (data) => {
      createdProductId = data._id;
    });
  });

  it('should fetch all products', async () => {
    const res = await tester.get(baseRoute, token);
    tester.assertFetched(res, 'product');
  });

  it('should return 404 for invalid product request', async () => {
    const fakeId = new mongoose.Types.ObjectId().toString();
    const res = await tester.get(`${baseRoute}/${fakeId}`, token);
    tester.assertNotFound(res, 'product');
  });
});
```

## ⚙️ Running Tests

Execute all tests or target a specific test suite using the Vitest runner:

```bash
# Run all tests in the project
npm run test

# Run only the branch test suite
npx vitest run src/tests/branch.test.ts
```
